   96: =head1 DESCRIPTION
   97: 
   98: =head2 What this module does
   99: 
  100: An I<abstract class> is a class that is only a template.  It holds code
  101: that its child classes share, but it is not complete on its own.  You
  102: should never make an object of it.  You make objects of its child classes
  103: instead.
  104: 
  105: Perl has no built-in way to say "this class is abstract".  This module
  106: adds one.  When code tries to make an object of an abstract class, the
  107: program dies with a clear error message.  Child classes work normally.
  108: 
  109: =head2 Terms used in this document
  110: 
  111: =over 4
  112: 
  113: =item class, package
  114: 
  115: In Perl, a class is a package.  C<Animal> and C<Dog> are package names.
  116: 
  117: =item parent class, child class, @ISA
  118: 
  119: Each package has a list called C<@ISA> that names its parent classes.
  120: If C<@Dog::ISA> contains C<Animal>, then C<Dog> is a child of C<Animal>,
  121: and C<Dog> can use C<Animal>'s methods.
  122: 
  123: =item abstract, concrete
  124: 
  125: A class is I<abstract> when C<Class::Abstract> is in its B<own> C<@ISA>.
  126: All other classes are I<concrete> (normal).
  127: 
  128: =item invocant
  129: 
  130: The value on the left of the arrow in a method call.  In
  131: C<< Dog->new >> the invocant is the string C<'Dog'>.  In
  132: C<< $rex->speak >> the invocant is the object C<$rex>.
  133: 
  134: =item croak, die
  135: 
  136: Stop the program (or the current C<eval> block) with an error message.
  137: 
  138: =item bypass
  139: 
  140: A setting that turns the check off.  See L</Turning the check off>.
  141: 
  142: =item test harness
  143: 
  144: The program that runs test files, for example C<prove> or C<make test>.
  145: It sets the environment variable C<HARNESS_ACTIVE>.
  146: 
  147: =back
  148: 
  149: =head2 How to make a class abstract
  150: 
  151: Put C<Class::Abstract> in the class's own C<@ISA>.  There are two ways:
  152: 
  153:     package Animal;
  154:     use parent 'Class::Abstract';    # way 1 (recommended)
  155: 
  156:     package Vehicle;
  157:     use Class::Abstract;             # way 2
  158: 
  159: Both ways have the same result.
  160: 
  161: =head2 How the check works
  162: 
  163: C<Class::Abstract> gives every class below it a method called C<new()>.
  164: When C<new()> runs, it looks at the invocant (the class name on the left
  165: of the arrow).  If that class has C<Class::Abstract> in its B<own>
  166: C<@ISA>, C<new()> dies.  If not, C<new()> makes and returns an empty
  167: object.
  168: 
  169: This is why child classes work.  When C<Dog> calls
  170: C<< $class->SUPER::new >>, the invocant is still C<'Dog'>, not
  171: C<'Animal'>.  C<Dog> does not have C<Class::Abstract> in its own C<@ISA>,
  172: so the check passes.
  173: 
  174: =head2 Only the class that asks is abstract
  175: 
  176: Being abstract is B<not> passed down to child classes.  If you want an
  177: abstract class below another abstract class, list C<Class::Abstract> in
  178: that class too:
  179: 
  180:     package Animal;   use parent 'Class::Abstract';               # abstract
  181:     package Mammal;   use parent 'Class::Abstract', 'Animal';     # also abstract
  182:     package Dog;      use parent -norequire, 'Mammal';            # concrete
  183: 
  184: =head2 Turning the check off
  185: 
  186: Sometimes a test needs an object of an abstract class.  Two settings turn
  187: the check off.  If B<either> one is on, the check is off.

  599: Tells you whether a class is abstract.  It returns C<1> (yes) or C<0>
  600: (no).

  602: A class is abstract only when C<Class::Abstract> is in its B<own>
  603: C<@ISA>, or when the class B<is> C<Class::Abstract>.  A child of an
  604: abstract class is B<not> abstract, so C<is_abstract()> returns C<0> for
  605: it.
  606: 
  607: Every class below C<Class::Abstract> can call this method.

  610: 
  611: =over 4
  612: 
  613: =item C<$self>
  614: 
  615: Required.  The class name or object on the left of the arrow.  If no target is given (see
  616: below), this is the class that is checked.
  617:

  619: 
  620: A class name or an object to check B<instead of> the invocant.  This is
  621: how you ask about any class: C<< Class::Abstract->is_abstract('Dog') >>.

  624: =back

  627: 
  628: The integer C<1> if the class is abstract, otherwise the integer C<0>.
  629: 
  630: A class name that does not exist (for example, a spelling mistake) gives
  631: C<0>, not an error.

  633: =head3 SIDE EFFECTS
  634: 
  635: None.  Asking about a class that does not exist does B<not> create it.
  636: 
  637: It does not change the global variables C<$_>, C<$@> or C<$!>, and it

  899: =head1 COMMON PITFALLS
  900: 
  901: =over 4
  902: 
  903: =item Your own new() skips the check
  904: 
  905: If an abstract class writes its own C<new()> and creates the object
  906: with C<bless>, C<Class::Abstract::new()> never runs.  Nothing stops
  907: C<< Shape->new >>.  Fix: call
  908: C<Class::Abstract::check_abstract($class)> on the first line, or build
  909: the object with C<< $class->SUPER::new >>.
  910: 
  911: =item The order of parents matters
  912: 
  913: Perl uses the B<first> C<new()> it finds, reading C<@ISA> from left to
  914: right.  In C<use parent 'Animal', 'Class::Abstract'>, Perl finds
  915: C<Animal::new> first, if C<Animal> has one.  If that C<new()> does not
  916: call C<check_abstract()>, there is no check.
  917: 
  918: =item Child classes are not abstract automatically
  919: 
  920: C<Mammal> below the abstract class C<Animal> is B<concrete> unless
  921: C<Mammal> also lists C<Class::Abstract> in its own C<@ISA>.
  922: 
  923: =item "use Class::Abstract;" changes the current package
  924: 
  925: C<use Class::Abstract;> makes the package it is written in abstract.  If
  926: you write it in a script only to call C<is_abstract()>, the C<main>
  927: package becomes abstract.  Write C<use Class::Abstract ();> instead.
  928: With the empty list, Perl does not call C<import()>.  The same is true
  929: for C<require Class::Abstract;>: it does B<not> make any class abstract.
  930: 
  931: =item undef and empty strings
  932: 
  933: C<< Class::Abstract::new(undef) >>, C<new('')> and the same calls to
  934: C<check_abstract()> and C<is_abstract()> die.  But an C<undef>
  935: B<target> in C<< $obj->is_abstract(undef) >> is treated as "no target",
  936: so the invocant is checked.
  937: 
  938: =item Spelling mistakes give 0, not an error
  939: 
  940: C<< Class::Abstract->is_abstract('Anmial') >> returns C<0>, because no
  941: package with that name has C<Class::Abstract> in its C<@ISA>.  Check
  942: the spelling if you get C<0> when you expect C<1>.
  943: 
  944: =item A bypass without "local" never ends
  945: 
  946: C<$Class::Abstract::BYPASS = 1;> without C<local> turns the check off
  947: for the rest of the program, in every file.
  948: 
  949: =item Strings that look false are true
  950: 
  951: C<$BYPASS = 'false'> and C<$BYPASS = 'no'> turn the check B<off>,
  952: because Perl treats every non-empty string except C<'0'> as true.  Use
  953: C<1> and C<0>.
  954: 
  955: =item $BYPASS wins over harness_bypass
  956: 
  957: If C<$BYPASS> is true, setting C<harness_bypass> to C<0> does not turn
  958: the check on.  To be sure the check is on, set both:
  959: 
  960:     local $Class::Abstract::BYPASS                 = 0;
  961:     local $Class::Abstract::config{harness_bypass} = 0;
  962: 
  963: =item Tests that passed before 0.03 may now die
  964: 
  965: Before version 0.03 the check was off inside a test harness.  If your
  966: tests make objects of abstract classes, they will now die.  See
  967: L</Turning the check off>.
  968: 
  969: =item isa() is not the same as is_abstract()
  970: 
  971: C<< Dog->isa('Class::Abstract') >> is true, because C<Class::Abstract>
  972: is a grandparent of C<Dog>.  Use C<< Dog->is_abstract >> to ask whether
  973: C<Dog> itself is abstract.
  974: 
  975: =item new() throws away its arguments
  976: 
  977: C<< Dog->SUPER::new(name => 'Rex') >> does not store C<name>.  Store it
  978: yourself after C<SUPER::new> returns.
  979: 
  980: =item Objects made during a bypass stay abstract
  981: 
  982: An object made while the bypass was on still belongs to the abstract
  983: class.  Calling C<< $obj->new >> on it later, with the check on, dies.
  984: 
  985: =back

 1032: =head1 LIMITATIONS
 1033: 
 1034: =over 4
 1035: 
 1036: =item Only the check in new() and check_abstract() protects a class
 1037: 
 1038: Code can still make an object of an abstract class with
 1039: C<bless {}, 'Animal'>, with L<Storable/dclone>, with C<thaw>, or with a
 1040: C<new()> that forgets to call C<check_abstract()>.  The check is a rule
 1041: that the module follows when it is asked.  It is not built into Perl.
 1042: 
 1043: =item can('new') returns a method that dies
 1044: 
 1045: C<< Animal->can('new') >> returns C<\&Class::Abstract::new>.  This looks
 1046: like "yes, you can call new()".  You can call it, but it dies.
 1047: 
 1048: =item The bypass is global
 1049: 
 1050: C<$BYPASS> turns the check off for every class, not only for the class
 1051: that a test is about.
 1052: 
 1053: =item The old package separator is not supported
 1054: 
 1055: Perl once allowed C<'> between parts of a package name (C<Foo'Bar>
 1056: meaning C<Foo::Bar>).  This module does not convert C<'> to C<::>, so
 1057: such names are treated as concrete.
 1058: 
 1059: =item Threads
 1060: 
 1061: The module shares no data between threads, except C<$BYPASS> and
 1062: C<%config>, which are normally only read.  C<import()> changes the
 1063: caller's C<@ISA>, usually when the program is compiled.  This is safe if
 1064: modules are not loaded with C<require> from several threads at once.
 1065: 
 1066: =item Not for Moo or Moose
 1067: 
 1068: Moo and Moose have their own ways to make abstract classes and required
 1069: methods.  This module is for plain Perl classes.
 1070: 
 1071: =back

 1217: =head1 STATE DIAGRAM
 1218: 
 1219: The module has two independent kinds of state: the state of B<each
 1220: class>, and the global B<check mode>.
 1221: 
 1222: =head2 Class states
 1223: 
 1224: Every package is in exactly one of these states:
 1225: 
 1226:     MISSING    The package does not exist yet.
 1227:     PLAIN      The package exists.  Class::Abstract is not one of its
 1228:                ancestors, so it has no new() from this module.
 1229:     ABSTRACT   'Class::Abstract' is in the package's own @ISA.
 1230:     CONCRETE   The package inherits from an abstract class, but
 1231:                'Class::Abstract' is not in its own @ISA.
 1232: 
 1233: Transitions:
 1234: 
 1235:                        use Class::Abstract;
 1236:                        use parent 'Class::Abstract';
 1237:                        push @P::ISA, 'Class::Abstract'
 1238:         +---------+  ------------------------------->  +----------+
 1239:         | MISSING |                                    |          |
 1240:         +---------+                                    |          |
 1241:           |     |                                      |          |
 1242:           |     | Class::Abstract::new('P')            |          |
 1243:           |     | (bless creates P)                    | ABSTRACT |
 1244:           |     v                                      |          |
 1245:           |  +-------+   same triggers as above        |          |
 1246:           |  | PLAIN | ------------------------------> |          |
 1247:           |  |       | <------------------------------ |          |
 1248:           |  +-------+   remove 'Class::Abstract'      +----------+
 1249:           |     |        from @P::ISA (P->new now          ^   |
 1250:           |     |        fails: "Can't locate object       |   | remove
 1251:           |     |        method new")                      |   | 'Class::Abstract'
 1252:           |     | @P::ISA = ('Animal')                     |   | from @P::ISA
 1253:           |     | (Animal is ABSTRACT or CONCRETE)         |   | (an abstract
 1254:           |     v                                    add   |   | parent remains)
 1255:           |  +----------+  ----------------------------->--+   |
 1256:           +->| CONCRETE |   use parent 'Class::Abstract'       |
 1257:              |          |  <-----------------------------------+
 1258:              +----------+
 1259: 
 1260:     @P::ISA = ('Animal') also moves MISSING directly to CONCRETE.
 1261:

 1263: 
 1264:     P->is_abstract, Class::Abstract->is_abstract('P')   any state  -> same state
 1265:     Class::Abstract::check_abstract('P')                any state  -> same state

 1271:     |           | -------------------------------------------------> |          |
