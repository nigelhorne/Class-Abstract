   98: =head1 DESCRIPTION
   99: 
  100: =head2 What this module does
  101: 
  102: An I<abstract class> is a class that is only a template.  It holds code
  103: that its child classes share, but it is not complete on its own.  You
  104: should never make an object of it.  You make objects of its child classes
  105: instead.
  106: 
  107: Perl has no built-in way to say "this class is abstract".  This module
  108: adds one.  When code tries to make an object of an abstract class, the
  109: program dies with a clear error message.  Child classes work normally.
  110: 
  111: =head2 Terms used in this document
  112: 
  113: =over 4
  114: 
  115: =item class, package
  116: 
  117: In Perl, a class is a package.  C<Animal> and C<Dog> are package names.
  118: 
  119: =item parent class, child class, @ISA
  120: 
  121: Each package has a list called C<@ISA> that names its parent classes.
  122: If C<@Dog::ISA> contains C<Animal>, then C<Dog> is a child of C<Animal>,
  123: and C<Dog> can use C<Animal>'s methods.
  124: 
  125: =item abstract, concrete
  126: 
  127: A class is I<abstract> when C<Class::Abstract> is in its B<own> C<@ISA>.
  128: All other classes are I<concrete> (normal).
  129: 
  130: =item invocant
  131: 
  132: The value on the left of the arrow in a method call.  In
  133: C<< Dog->new >> the invocant is the string C<'Dog'>.  In
  134: C<< $rex->speak >> the invocant is the object C<$rex>.
  135: 
  136: =item croak, die
  137: 
  138: Stop the program (or the current C<eval> block) with an error message.
  139: 
  140: =item bypass
  141: 
  142: A setting that turns the check off.  See L</Turning the check off>.
  143: 
  144: =item test harness
  145: 
  146: The program that runs test files, for example C<prove> or C<make test>.
  147: It sets the environment variable C<HARNESS_ACTIVE>.
  148: 
  149: =back
  150: 
  151: =head2 How to make a class abstract
  152: 
  153: Put C<Class::Abstract> in the class's own C<@ISA>.  There are two ways:
  154: 
  155:     package Animal;
  156:     use parent 'Class::Abstract';    # way 1 (recommended)
  157: 
  158:     package Vehicle;
  159:     use Class::Abstract;             # way 2
  160: 
  161: Both ways have the same result.
  162: 
  163: =head2 How the check works
  164: 
  165: C<Class::Abstract> gives every class below it a method called C<new()>.
  166: When C<new()> runs, it looks at the invocant (the class name on the left
  167: of the arrow).  If that class has C<Class::Abstract> in its B<own>
  168: C<@ISA>, C<new()> dies.  If not, C<new()> makes and returns an empty
  169: object.
  170: 
  171: This is why child classes work.  When C<Dog> calls
  172: C<< $class->SUPER::new >>, the invocant is still C<'Dog'>, not
  173: C<'Animal'>.  C<Dog> does not have C<Class::Abstract> in its own C<@ISA>,
  174: so the check passes.
  175: 
  176: =head2 Only the class that asks is abstract
  177: 
  178: Being abstract is B<not> passed down to child classes.  If you want an
  179: abstract class below another abstract class, list C<Class::Abstract> in
  180: that class too:
  181: 
  182:     package Animal;   use parent 'Class::Abstract';               # abstract
  183:     package Mammal;   use parent 'Class::Abstract', 'Animal';     # also abstract
  184:     package Dog;      use parent -norequire, 'Mammal';            # concrete
  185: 
  186: =head2 Turning the check off
  187: 
  188: Sometimes a test needs an object of an abstract class.  Two settings turn
  189: the check off.  If B<either> one is on, the check is off.
  190: 
  191: =over 4
  192: 
  193: =item 1. The variable C<$Class::Abstract::BYPASS>
  194: 
  195: Set it to a true value.  Always use C<local>, so the setting ends at the
  196: end of the block:
  197: 
  198:     my $animal = do { local $Class::Abstract::BYPASS = 1; Animal->new };
  199: 
  200: =item 2. The setting C<harness_bypass> together with a test harness
  201: 
  202: If C<< $Class::Abstract::config{harness_bypass} >> is true B<and> the
  203: environment variable C<HARNESS_ACTIVE> is true, the check is off.
  204: C<harness_bypass> is false by default, so the check is B<on> in your
  205: tests unless you change it.
  206: 
  207: =back
  208: 
  209: C<$BYPASS> is checked first.  If C<$BYPASS> is true, setting
  210: C<harness_bypass> to 0 does B<not> turn the check back on.
  211: 
  212: B<Changed in version 0.03:> before 0.03, C<harness_bypass> was 1 by

  214: the old behaviour back, put this near the top of your test files:
  215: 
  216:     $Class::Abstract::config{harness_bypass} = 1;

  881: =head1 COMMON PITFALLS
  882: 
  883: =over 4
  884: 
  885: =item Your own new() skips the check
  886: 
  887: If an abstract class writes its own C<new()> and creates the object
  888: with C<bless>, C<Class::Abstract::new()> never runs.  Nothing stops
  889: C<< Shape->new >>.  Fix: call
  890: C<Class::Abstract::check_abstract($class)> on the first line, or build
  891: the object with C<< $class->SUPER::new >>.
  892: 
  893: =item The order of parents matters
  894: 
  895: Perl uses the B<first> C<new()> it finds, reading C<@ISA> from left to
  896: right.  In C<use parent 'Animal', 'Class::Abstract'>, Perl finds
  897: C<Animal::new> first, if C<Animal> has one.  If that C<new()> does not
  898: call C<check_abstract()>, there is no check.
  899: 
  900: =item Child classes are not abstract automatically
  901: 
  902: C<Mammal> below the abstract class C<Animal> is B<concrete> unless
  903: C<Mammal> also lists C<Class::Abstract> in its own C<@ISA>.
  904: 
  905: =item "use Class::Abstract;" changes the current package
  906: 
  907: C<use Class::Abstract;> makes the package it is written in abstract.  If
  908: you write it in a script only to call C<is_abstract()>, the C<main>
  909: package becomes abstract.  Write C<use Class::Abstract ();> instead.
  910: With the empty list, Perl does not call C<import()>.  The same is true
  911: for C<require Class::Abstract;>: it does B<not> make any class abstract.
  912: 
  913: =item undef and empty strings
  914: 
  915: C<< Class::Abstract::new(undef) >>, C<new('')> and the same calls to
  916: C<check_abstract()> and C<is_abstract()> die.  But an C<undef>
  917: B<target> in C<< $obj->is_abstract(undef) >> is treated as "no target",
  918: so the invocant is checked.
  919: 
  920: =item Spelling mistakes give 0, not an error
  921: 
  922: C<< Class::Abstract->is_abstract('Anmial') >> returns C<0>, because no
  923: package with that name has C<Class::Abstract> in its C<@ISA>.  Check
  924: the spelling if you get C<0> when you expect C<1>.
  925: 
  926: =item A bypass without "local" never ends
  927: 
  928: C<$Class::Abstract::BYPASS = 1;> without C<local> turns the check off
  929: for the rest of the program, in every file.
  930: 
  931: =item Strings that look false are true
  932: 
  933: C<$BYPASS = 'false'> and C<$BYPASS = 'no'> turn the check B<off>,
  934: because Perl treats every non-empty string except C<'0'> as true.  Use
  935: C<1> and C<0>.
  936: 
  937: =item $BYPASS wins over harness_bypass
  938: 
  939: If C<$BYPASS> is true, setting C<harness_bypass> to C<0> does not turn
  940: the check on.  To be sure the check is on, set both:
  941: 
  942:     local $Class::Abstract::BYPASS                 = 0;
  943:     local $Class::Abstract::config{harness_bypass} = 0;
  944: 
  945: =item Tests that passed before 0.03 may now die
  946: 
  947: Before version 0.03 the check was off inside a test harness.  If your
  948: tests make objects of abstract classes, they will now die.  See
  949: L</Turning the check off>.
  950: 
  951: =item isa() is not the same as is_abstract()
  952: 
  953: C<< Dog->isa('Class::Abstract') >> is true, because C<Class::Abstract>
  954: is a grandparent of C<Dog>.  Use C<< Dog->is_abstract >> to ask whether
  955: C<Dog> itself is abstract.
  956: 
  957: =item new() throws away its arguments
  958: 
  959: C<< Dog->SUPER::new(name => 'Rex') >> does not store C<name>.  Store it
  960: yourself after C<SUPER::new> returns.
  961: 
  962: =item Objects made during a bypass stay abstract
  963: 
  964: An object made while the bypass was on still belongs to the abstract
  965: class.  Calling C<< $obj->new >> on it later, with the check on, dies.
  966: 
  967: =back

  969: =head1 ENCODING
  970: 
  971: The module does not read files, the terminal or the network.  The only
  972: text it handles is class names, and the error messages that contain them.
  973: 
  974: =over 4
  975: 
  976: =item Class names
  977: 
  978: Class names may contain any characters that Perl allows in a package
  979: name.  This includes non-ASCII letters (C<CafE<eacute>>, Japanese,
  980: Chinese) and, for names made with C<bless> or symbolic references, emoji.
  981: The module compares names exactly, character by character.
  982: 
  983: Two conditions apply:
  984: 
  985: =over 4
  986: 
  987: =item * Non-ASCII package names need Perl 5.16 or later.  The rest of
  988: the module works on Perl 5.8.
  989: 
  990: =item * The name must be a B<character string>, not raw UTF-8 bytes.
  991: Names written in source code under C<use utf8;> are character strings.
  992: Names read from a file or the network must be decoded first (for example
  993: with L<Encode/decode>).  A name that is still raw bytes is a B<different>
  994: name to Perl, so C<is_abstract()> returns C<0> for it.
  995: 
  996: =back

  999: 
 1000: The fixed text of every message is plain ASCII English.  A message also

 1002: print such a message to a file handle that has no encoding layer, Perl
 1003: warns C<Wide character in print>.  Add a layer to avoid this:
 1004:

 1008: 
 1009: C<$BYPASS>, C<harness_bypass> and C<HARNESS_ACTIVE> are only tested for
 1010: true or false.  Their text is never used.

 1014: =head1 LIMITATIONS
 1015: 
 1016: =over 4
 1017: 
 1018: =item Only the check in new() and check_abstract() protects a class
 1019: 
 1020: Code can still make an object of an abstract class with
 1021: C<bless {}, 'Animal'>, with L<Storable/dclone>, with C<thaw>, or with a
 1022: C<new()> that forgets to call C<check_abstract()>.  The check is a rule
 1023: that the module follows when it is asked.  It is not built into Perl.
 1024: 
 1025: =item can('new') returns a method that dies
 1026: 
 1027: C<< Animal->can('new') >> returns C<\&Class::Abstract::new>.  This looks
 1028: like "yes, you can call new()".  You can call it, but it dies.
 1029: 
 1030: =item The bypass is global
 1031: 
 1032: C<$BYPASS> turns the check off for every class, not only for the class
 1033: that a test is about.
 1034: 
 1035: =item The old package separator is not supported
 1036: 
 1037: Perl once allowed C<'> between parts of a package name (C<Foo'Bar>
 1038: meaning C<Foo::Bar>).  This module does not convert C<'> to C<::>, so
 1039: such names are treated as concrete.
 1040: 
 1041: =item Threads
 1042: 
 1043: The module shares no data between threads, except C<$BYPASS> and
 1044: C<%config>, which are normally only read.  C<import()> changes the
 1045: caller's C<@ISA>, usually when the program is compiled.  This is safe if
 1046: modules are not loaded with C<require> from several threads at once.
 1047: 
 1048: =item Not for Moo or Moose
 1049: 
 1050: Moo and Moose have their own ways to make abstract classes and required
 1051: methods.  This module is for plain Perl classes.
 1052: 
 1053: =back

 1197: =head1 STATE DIAGRAM
 1198: 
 1199: The module has two independent kinds of state: the state of B<each
 1200: class>, and the global B<check mode>.
 1201: 
 1202: =head2 Class states
 1203: 
 1204: Every package is in exactly one of these states:
 1205: 
 1206:     MISSING    The package does not exist yet.
 1207:     PLAIN      The package exists.  Class::Abstract is not one of its
 1208:                ancestors, so it has no new() from this module.
 1209:     ABSTRACT   'Class::Abstract' is in the package's own @ISA.
 1210:     CONCRETE   The package inherits from an abstract class, but
 1211:                'Class::Abstract' is not in its own @ISA.
 1212: 
 1213: Transitions:
 1214: 
 1215:                        use Class::Abstract;
 1216:                        use parent 'Class::Abstract';
 1217:                        push @P::ISA, 'Class::Abstract'
 1218:         +---------+  ------------------------------->  +----------+
 1219:         | MISSING |                                    |          |
 1220:         +---------+                                    |          |
 1221:           |     |                                      |          |
 1222:           |     | Class::Abstract::new('P')            |          |
 1223:           |     | (bless creates P)                    | ABSTRACT |
 1224:           |     v                                      |          |
 1225:           |  +-------+   same triggers as above        |          |
 1226:           |  | PLAIN | ------------------------------> |          |
 1227:           |  |       | <------------------------------ |          |
 1228:           |  +-------+   remove 'Class::Abstract'      +----------+
 1229:           |     |        from @P::ISA (P->new now          ^   |
 1230:           |     |        fails: "Can't locate object       |   | remove
 1231:           |     |        method new")                      |   | 'Class::Abstract'
 1232:           |     | @P::ISA = ('Animal')                     |   | from @P::ISA
 1233:           |     | (Animal is ABSTRACT or CONCRETE)         |   | (an abstract
 1234:           |     v                                    add   |   | parent remains)
 1235:           |  +----------+  ----------------------------->--+   |
 1236:           +->| CONCRETE |   use parent 'Class::Abstract'       |
 1237:              |          |  <-----------------------------------+
 1238:              +----------+
 1239: 
 1240:     @P::ISA = ('Animal') also moves MISSING directly to CONCRETE.
 1241: 
 1242: Calls that never change a class's state:
 1243: 
 1244:     P->is_abstract, Class::Abstract->is_abstract('P')   any state  -> same state
 1245:     Class::Abstract::check_abstract('P')                any state  -> same state
 1246:     use Class::Abstract;  (again, in P)                 ABSTRACT   -> ABSTRACT
