   96: =head1 DESCRIPTION
   97: 
   98: =head2 What this module does
   99: 
  100: An I<abstract class> is a class that is only a template.  It holds code
  101: that its child classes share, but it is not complete on its own.  You
  102: should never make an object of it.  You make objects of its child classes
  103: instead.
  104: 
  105: Perl has no built-in way to say "this class is abstract".  This module
  106: adds one.  When code tries to make an object of an abstract class, the
  107: program dies with a clear error message.  Child classes work normally.
  108: 
  109: =head2 Terms used in this document
  110: 
  111: =over 4
  112: 
  113: =item class, package
  114: 
  115: In Perl, a class is a package.  C<Animal> and C<Dog> are package names.
  116: 
  117: =item parent class, child class, @ISA
  118: 
  119: Each package has a list called C<@ISA> that names its parent classes.
  120: If C<@Dog::ISA> contains C<Animal>, then C<Dog> is a child of C<Animal>,
  121: and C<Dog> can use C<Animal>'s methods.
  122: 
  123: =item abstract, concrete
  124: 
  125: A class is I<abstract> when C<Class::Abstract> is in its B<own> C<@ISA>.
  126: All other classes are I<concrete> (normal).
  127: 
  128: =item invocant
  129: 
  130: The value on the left of the arrow in a method call.  In
  131: C<< Dog->new >> the invocant is the string C<'Dog'>.  In
  132: C<< $rex->speak >> the invocant is the object C<$rex>.
  133: 
  134: =item croak, die
  135: 
  136: Stop the program (or the current C<eval> block) with an error message.
  137: 
  138: =item bypass
  139: 
  140: A setting that turns the check off.  See L</Turning the check off>.
  141: 
  142: =item test harness
  143: 
  144: The program that runs test files, for example C<prove> or C<make test>.
  145: It sets the environment variable C<HARNESS_ACTIVE>.
  146: 
  147: =back
  148: 
  149: =head2 How to make a class abstract
  150: 
  151: Put C<Class::Abstract> in the class's own C<@ISA>.  There are two ways:
  152: 
  153:     package Animal;
  154:     use parent 'Class::Abstract';    # way 1 (recommended)
  155: 
  156:     package Vehicle;
  157:     use Class::Abstract;             # way 2
  158: 
  159: Both ways have the same result.
  160: 
  161: =head2 How the check works
  162: 
  163: C<Class::Abstract> gives every class below it a method called C<new()>.
  164: When C<new()> runs, it looks at the invocant (the class name on the left
  165: of the arrow).  If that class has C<Class::Abstract> in its B<own>
  166: C<@ISA>, C<new()> dies.  If not, C<new()> makes and returns an empty
  167: object.
  168: 
  169: This is why child classes work.  When C<Dog> calls
  170: C<< $class->SUPER::new >>, the invocant is still C<'Dog'>, not
  171: C<'Animal'>.  C<Dog> does not have C<Class::Abstract> in its own C<@ISA>,
  172: so the check passes.
  173: 
  174: =head2 Only the class that asks is abstract
  175: 
  176: Being abstract is B<not> passed down to child classes.  If you want an
  177: abstract class below another abstract class, list C<Class::Abstract> in
  178: that class too:
  179: 
  180:     package Animal;   use parent 'Class::Abstract';               # abstract
  181:     package Mammal;   use parent 'Class::Abstract', 'Animal';     # also abstract
  182:     package Dog;      use parent -norequire, 'Mammal';            # concrete
  183: 
  184: =head2 Turning the check off
  185: 
  186: Sometimes a test needs an object of an abstract class.  Two settings turn
  187: the check off.  If B<either> one is on, the check is off.
  188: 
  189: =over 4
  190: 
  191: =item 1. The variable C<$Class::Abstract::BYPASS>

  193: Set it to a true value.  Always use C<local>, so the setting ends at the
  194: end of the block:

  196:     my $animal = do { local $Class::Abstract::BYPASS = 1; Animal->new };

  198: =item 2. The setting C<harness_bypass> together with a test harness

  200: If C<< $Class::Abstract::config{harness_bypass} >> is true B<and> the

  202: C<harness_bypass> is false by default, so the check is B<on> in your

  205: =back

  207: C<$BYPASS> is checked first.  If C<$BYPASS> is true, setting

  905: =head1 COMMON PITFALLS
  906: 
  907: =over 4
  908: 
  909: =item Your own new() skips the check
  910: 
  911: If an abstract class writes its own C<new()> and creates the object
  912: with C<bless>, C<Class::Abstract::new()> never runs.  Nothing stops
  913: C<< Shape->new >>.  Fix: call
  914: C<Class::Abstract::check_abstract($class)> on the first line, or build
  915: the object with C<< $class->SUPER::new >>.
  916: 
  917: =item The order of parents matters
  918: 
  919: Perl uses the B<first> C<new()> it finds, reading C<@ISA> from left to
  920: right.  In C<use parent 'Animal', 'Class::Abstract'>, Perl finds
  921: C<Animal::new> first, if C<Animal> has one.  If that C<new()> does not
  922: call C<check_abstract()>, there is no check.
  923: 
  924: =item Child classes are not abstract automatically
  925: 
  926: C<Mammal> below the abstract class C<Animal> is B<concrete> unless
  927: C<Mammal> also lists C<Class::Abstract> in its own C<@ISA>.
  928: 
  929: =item "use Class::Abstract;" changes the current package
  930: 
  931: C<use Class::Abstract;> makes the package it is written in abstract.  If
  932: you write it in a script only to call C<is_abstract()>, the C<main>
  933: package becomes abstract.  Write C<use Class::Abstract ();> instead.
  934: With the empty list, Perl does not call C<import()>.  The same is true
  935: for C<require Class::Abstract;>: it does B<not> make any class abstract.
  936: 
  937: =item undef and empty strings
  938: 
  939: C<< Class::Abstract::new(undef) >>, C<new('')> and the same calls to
  940: C<check_abstract()> and C<is_abstract()> die.  But an C<undef>
  941: B<target> in C<< $obj->is_abstract(undef) >> is treated as "no target",
  942: so the invocant is checked.
  943: 
  944: =item Spelling mistakes give 0, not an error
  945: 
  946: C<< Class::Abstract->is_abstract('Anmial') >> returns C<0>, because no
  947: package with that name has C<Class::Abstract> in its C<@ISA>.  Check
  948: the spelling if you get C<0> when you expect C<1>.
  949: 
  950: =item A bypass without "local" never ends
  951: 
  952: C<$Class::Abstract::BYPASS = 1;> without C<local> turns the check off
  953: for the rest of the program, in every file.
  954: 
  955: =item Strings that look false are true
  956: 
  957: C<$BYPASS = 'false'> and C<$BYPASS = 'no'> turn the check B<off>,
  958: because Perl treats every non-empty string except C<'0'> as true.  Use
  959: C<1> and C<0>.
  960: 
  961: =item $BYPASS wins over harness_bypass
  962: 
  963: If C<$BYPASS> is true, setting C<harness_bypass> to C<0> does not turn
  964: the check on.  To be sure the check is on, set both:
  965: 
  966:     local $Class::Abstract::BYPASS                 = 0;
  967:     local $Class::Abstract::config{harness_bypass} = 0;
  968: 
  969: =item Tests that passed before 0.03 may now die
  970: 
  971: Before version 0.03 the check was off inside a test harness.  If your
  972: tests make objects of abstract classes, they will now die.  See
  973: L</Turning the check off>.
  974: 
  975: =item isa() is not the same as is_abstract()
  976: 
  977: C<< Dog->isa('Class::Abstract') >> is true, because C<Class::Abstract>
  978: is a grandparent of C<Dog>.  Use C<< Dog->is_abstract >> to ask whether
  979: C<Dog> itself is abstract.
  980: 
  981: =item new() throws away its arguments
  982: 
  983: C<< Dog->SUPER::new(name => 'Rex') >> does not store C<name>.  Store it
  984: yourself after C<SUPER::new> returns.

  986: =item Objects made during a bypass stay abstract
  987: 
  988: An object made while the bypass was on still belongs to the abstract
  989: class.  Calling C<< $obj->new >> on it later, with the check on, dies.

 1038: =head1 LIMITATIONS
 1039: 
 1040: =over 4
 1041: 
 1042: =item Only the check in new() and check_abstract() protects a class
 1043: 
 1044: Code can still make an object of an abstract class with
 1045: C<bless {}, 'Animal'>, with L<Storable/dclone>, with C<thaw>, or with a
 1046: C<new()> that forgets to call C<check_abstract()>.  The check is a rule
 1047: that the module follows when it is asked.  It is not built into Perl.
 1048: 
 1049: =item can('new') returns a method that dies
 1050: 
 1051: C<< Animal->can('new') >> returns C<\&Class::Abstract::new>.  This looks
 1052: like "yes, you can call new()".  You can call it, but it dies.
 1053: 
 1054: =item The bypass is global
 1055: 
 1056: C<$BYPASS> turns the check off for every class, not only for the class
 1057: that a test is about.
 1058: 
 1059: =item The old package separator is not supported
 1060: 
 1061: Perl once allowed C<'> between parts of a package name (C<Foo'Bar>
 1062: meaning C<Foo::Bar>).  This module does not convert C<'> to C<::>, so
 1063: such names are treated as concrete.
 1064: 
 1065: =item Threads
 1066: 
 1067: The module shares no data between threads, except C<$BYPASS> and
 1068: C<%config>, which are normally only read.  C<import()> changes the
 1069: caller's C<@ISA>, usually when the program is compiled.  This is safe if
 1070: modules are not loaded with C<require> from several threads at once.
 1071: 
 1072: =item Not for Moo or Moose
 1073: 
 1074: Moo and Moose have their own ways to make abstract classes and required
 1075: methods.  This module is for plain Perl classes.
 1076:

 1223: =head1 STATE DIAGRAM
 1224: 
 1225: The module has two independent kinds of state: the state of B<each
 1226: class>, and the global B<check mode>.
 1227: 
 1228: =head2 Class states
 1229: 
 1230: Every package is in exactly one of these states:
 1231: 
 1232:     MISSING    The package does not exist yet.
 1233:     PLAIN      The package exists.  Class::Abstract is not one of its
 1234:                ancestors, so it has no new() from this module.
 1235:     ABSTRACT   'Class::Abstract' is in the package's own @ISA.
 1236:     CONCRETE   The package inherits from an abstract class, but
 1237:                'Class::Abstract' is not in its own @ISA.
 1238: 
 1239: Transitions:
 1240: 
 1241:                        use Class::Abstract;
 1242:                        use parent 'Class::Abstract';
 1243:                        push @P::ISA, 'Class::Abstract'
 1244:         +---------+  ------------------------------->  +----------+
 1245:         | MISSING |                                    |          |
 1246:         +---------+                                    |          |
 1247:           |     |                                      |          |
 1248:           |     | Class::Abstract::new('P')            |          |
 1249:           |     | (bless creates P)                    | ABSTRACT |
 1250:           |     v                                      |          |
 1251:           |  +-------+   same triggers as above        |          |
 1252:           |  | PLAIN | ------------------------------> |          |
 1253:           |  |       | <------------------------------ |          |
 1254:           |  +-------+   remove 'Class::Abstract'      +----------+
 1255:           |     |        from @P::ISA (P->new now          ^   |
 1256:           |     |        fails: "Can't locate object       |   | remove
 1257:           |     |        method new")                      |   | 'Class::Abstract'
 1258:           |     | @P::ISA = ('Animal')                     |   | from @P::ISA
 1259:           |     | (Animal is ABSTRACT or CONCRETE)         |   | (an abstract
 1260:           |     v                                    add   |   | parent remains)
 1261:           |  +----------+  ----------------------------->--+   |
 1262:           +->| CONCRETE |   use parent 'Class::Abstract'       |
 1263:              |          |  <-----------------------------------+
 1264:              +----------+
 1265: 
 1266:     @P::ISA = ('Animal') also moves MISSING directly to CONCRETE.
 1267:

 1269: 
 1270:     P->is_abstract, Class::Abstract->is_abstract('P')   any state  -> same state
 1271:     Class::Abstract::check_abstract('P')                any state  -> same state
